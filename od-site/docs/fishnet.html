00 / Addon

What the addon does

An optional package that lives in Assets/FBSystemFishNet/. It turns any scene and any FBSystem player into a FishNet-multiplayer setup without touching the base package.

  • A 4-step Setup Wizard wires NetworkManager, the player bridge and world items — idempotently, existing objects are reused.
  • FishNetPlayerBridge syncs movement, animator state, look pitch and item equipment and auto-discovers owner-only components (ItemSwitcher, PlayerInteraction, PlayerDropSystem).
  • FishNetFPCutterVisibility hides the head for the local player (no FP clipping) and shows the full body on every remote.
  • A drag-&-drop world-item window creates _Net variants, registers them, and fills the bridge prefab list.
  • A prepared demo scene is included and added to Build Settings.

03 / 2

2. FishNet Setup Wizard

Menu: Tools ▸ FBSystem ▸ FishNet ▸ Setup Wizard. Ein 5-Schritt-Wizard (Header mit Icon, 5er-Fortschrittsleiste, Karten-Sektionen, < Back / Next > — Finish Setup). Der Wizard liegt ausschließlich in Assets/FBSystemFishNet und fasst Core-Dateien unter Assets/FBSystem nicht an — zum Export des Addons als .unitypackage nur den FishNet-Ordner exportieren. Jeder Schritt ist idempotent.

Step 1: Scene Setup

Bereitet die offene Szene als FishNet-Host vor:

  • Erstellt oder wiederverwendet NetworkManager mit Tugboat-Transport, ObserverManager, PlayerSpawner, Spawnable-Prefab-Verdrahtung und EventSystem.
  • Instanziiert FishNets eigenes NetworkHudCanvas-Prefab (Assets/FishNet/Demos/Prefabs/NetworkHudCanvas.prefab) für Start Server / Start Client. Wenn Demos entfernt wurden, zeigt der Wizard eine Warnung — Prefab wiederherstellen.
  • Alle Statuszeilen zeigen grün: NetworkManager, TransportManager + Tugboat, PlayerSpawner, Connection HUD, EventSystem. Button ✨ Make Scene FishNet Ready führt den Schritt aus.

Step 2: Select Player

Wähle das FBSystem-Player-GameObject aus der Hierarchy (Szene-Instanz — kein reines Prefab-Asset — mit PlayerController, Animator etc.). Der Wizard fügt NetworkObject und FishNetPlayerBridge hinzu und rekonfiguriert die Bridge falls vorhanden.

  • Feld Player Root: None (Game Object) → per Drag & Drop die Instanz aus der Szene ziehen.
  • Gelber Hinweis: Drag your player from the Hierarchy (scene instance). Prefab assets must be in a scene.
  • Bei FPCutter-Nutzung wird FishNetFPCutterVisibility automatisch verdrahtet — Kopf lokal versteckt, remote voll sichtbar.

Step 3: FishNet Components

Fügt und konfiguriert die Netzwerk-Komponenten — ohne Core-FBSystem-Dateien zu ändern:

  • NetworkObject, NetworkTransform (CharacterController, ClientAuth), NetworkAnimator (ClientAuth, Animator ref), FishNetPlayerBridge, FishNetFPCutterVisibility (local=FirstPerson / remote=ThirdPerson) — alle mit grünem Haken.
  • Info-Zeile bei erkanntem FPCutter: FPCutter mesh detected — FishNetFPCutterVisibility will hide Head for local player (no camera clipping) and show full body for remotes.
  • Button ✨ Configure FishNet Components. Unter Recent Changes erscheinen Configured NetworkObject / NetworkTransform / NetworkAnimator und FishNetFPCutterVisibility already present.

Step 4: World Items

Konvertiert WorldItem-Prefabs zu netzwerkfähigen Varianten (fügt NetworkObject + NetworkTransform hinzu, erzeugt *_Net.prefabs unter Assets/FBSystemFishNet/Testing/WorldItems/ und registriert sie als Spawnable):

  • Beispiel aus dem Screenshot: Found 2 item(s) in ItemContainer → [0] 1 -> Flashlightworlditem, [1] 2 -> Box_worlditem.
  • Button ✨ Setup Networked World Items (from ItemContainer) und Open WorldItem Setup Window (Drag & Drop, Find All, Remove) für manuelles Verwalten.
  • Hinweis: Für freies Hinzufügen per Drag & Drop Tools/FBSystem/FishNet/Setup Networked World Items (eigenes Fenster) nutzen.

Step 5: Validation

Finaler Health-Check. Behebe verbleibende Warnungen — dieser Schritt ändert keine Core-FBSystem-Dateien.

  • Bei Erfolg: ✨ All checks passed — the scene and player are ready for FishNet. Press Play and use FishNet's HUD buttons (Start Server / Start Client).
  • Button Select NetworkManager in Scene und Abschnitt Export: To ship the addon as .unitypackage: select Assets/FBSystemFishNet folder -> Right Click -> Export Package. Core Assets/FBSystem stays untouched and works without FishNet.
  • Wizard mit Finish Setup schließen. Der Wizard generiert bei Bedarf ein GeneratedPlayers/*_Network-Prefab-Asset, damit PlayerSpawner nie eine Szene-Instanz hält — das behebt PrefabId 65535 / NullReference beim Spawn.

Owner-only Behaviours (ItemSwitcher, PlayerInteraction, PlayerDropSystem) werden automatisch auf der Bridge erkannt.

04 / 3

3. Networked world items

Menu: Tools ▸ FBSystem ▸ FishNet ▸ Setup Networked World Items — a drag-&-drop window (NetworkWorldItemSetupWindow). Use Find All WorldItems, add or remove entries before applying, with Auto-Find Bridge and ItemContainer integration. It:

  • Creates _Net WorldItem variants.
  • Registers them with FishNet.
  • Fills the bridge's prefab list on the player.

Pickup despawns the server object; drop spawns a networked WorldItem visible to all clients (server authoritative).

06 / Limits

Not included by design

Out of scope for the addon

  • Item use stays local (no global sync).
  • Server prediction and authoritative movement correction — not yet implemented.
07 / Verify

Testing host & remote client

The addon ships a prepared test setup (already in Build Settings):

  • Scene: Assets/FBSystemFishNet/Testing/Demo.unity
  • Player: Assets/FBSystemFishNet/Testing/FBSystemNetworkPlayer.prefab
  • Collection: Assets/FBSystemFishNet/Testing/FBSystemFishNetPrefabs.asset

Host test in the editor

  1. Open Demo.unity — it must contain the FishNet NetworkManager prefab and its PlayerSpawner.
  2. Press Play. The HUD shows Start Server and Start Client. Start both for a host test.
  3. Verify movement, jump, sprint, crouch, root rotation, remote animator state and look pitch. The remote player must not process local input.
  4. Switch items (number keys, Q, or scroll) and verify equip/unequip on the other instance. Item use stays local.
  5. Stop the client first, then the server. Check the Console for bridge errors or movement-sanity warnings.

Remote-client test

  1. Build Demo.unity for Windows.
  2. Run the build as the client and the editor scene as the host.
  3. Start the server in the editor and the client in the build with the HUD buttons.
  4. Repeat the same verification as above across both instances.
Fix / Common issues

Troubleshooting

SymptomFix
PrefabId 65535 / NullReference on PlayerSpawner spawnRun the wizard's Validation step so PlayerSpawner holds a prefab asset (GeneratedPlayers/*_Network) registered in DefaultPrefabObjects — never a scene instance.
No Start Server / Start Client buttonsNetworkHudCanvas comes from FishNet/Demos/Prefabs. If you deleted Demos, the wizard warns — restore NetworkHudCanvas.prefab.
Remote head clips in FP / always hiddenPlayer needs FPCutterController. The addon wires FishNetFPCutterVisibility to hide the head locally and show the full body on remotes.
Equip not syncingEquip must go through ItemContainer slots (HandItemSocket.EquipFromContainer). Direct socket attaches without a slot carry no slot index.
Item RPCs rejectedServer sanity kicked after an invalid teleport or non-finite transform — fix the teleport driver before calling item code.
