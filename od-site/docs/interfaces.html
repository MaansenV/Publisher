Interfaces

The public runtime API of Easy FP Full Body Controller: the PlayerController hub, settings, input, locomotion, camera, items and item definitions, the event API, FPCutter, animation, foot planting, footsteps, finger grips, vitals and procedural IK. Everything lives in namespace Player unless noted.

07 / Events

Event API

Every equip, unequip, locomotion change, footstep and vitals change is announced in three ways:

MechanismFor
C# eventcode subscribers; struct payloads avoid per-call allocation
UnityEventInspector and no-code wiring
Listener interfacesstructured extension; any component in the player hierarchy that implements one is found automatically

Event payloads

StructFields
ItemEquipArgsItem (GameObject), SlotIndex (int, −1 if not from a container), HoldData (ItemHoldData), FromContainer (bool)
LandArgsImpactVelocity (float), FallDistance (float)
FootStepArgsIsLeft (bool), Point (Vector3), IsReStep (bool)

Item events: HandItemSocket

C# eventTypeUnityEvent
ItemEquippedAction<ItemEquipArgs>OnItemEquipped (ItemEvent, UnityEvent<GameObject>)
ItemUnequippedAction<ItemEquipArgs>OnItemUnequipped (ItemEvent)

With smooth transitions, ItemUnequipped fires while the old item is still visible, and ItemEquipped can fire for an item that is still waiting to be drawn.

Listener interfaces

Implement only the methods you need; the others are no-ops. Listeners on the player hierarchy are found at startup. Use RegisterListener for objects added at runtime.

  • IItemEventListener: OnItemEquipped(ItemEquipArgs), OnItemUnequipped(ItemEquipArgs)
  • ILocomotionEventListener: OnJumped(), OnLanded(LandArgs), OnCrouchStarted(), OnCrouchEnded(), OnSprintStarted(), OnSprintEnded(), OnGroundedChanged(bool)
using Player;
using UnityEngine;

public class MyListener : MonoBehaviour, IItemEventListener, ILocomotionEventListener
{
    public void OnItemEquipped(ItemEquipArgs args) => Debug.Log($"equipped {args.Item.name}");
    public void OnLanded(LandArgs args) => Debug.Log($"landed at {args.ImpactVelocity} m/s");
}
MethodNotes
locomotion.RegisterListener(ILocomotionEventListener)adds a locomotion listener at runtime
socket.RegisterListener(IItemEventListener)adds an item listener at runtime
UnregisterListener(...)removes a listener from either source

Subscribe in code

player.Locomotion.Jumped += () => Debug.Log("jumped");
player.HandItemSocket.ItemEquipped += args =>
    Debug.Log($"equipped {args.Item.name} from slot {args.SlotIndex}");

Event contract

Each transition fires its C# event and its UnityEvent once, from one place in the code.

10 / Feet, hands, head, vitals

Feet, hands, head and vitals

Most of these components are configured by the Setup Wizard. Adjust them directly only for advanced customization.

PlayerFootPlanting

On the model. Runs at execution order -200, before the camera syncs to the head. Keeps both feet anchored to the ground; a foot that drifts out of place takes a curved re-step. Step behaviour is set with StepSettings.

MemberSignature / typeNotes
SetEnabledSetEnabled(bool)toggles planting at runtime
ResetPlantingResetPlanting()resets the anchors (call after teleporting)
SetExternalDriveState / ClearExternalDriveStateSetExternalDriveState(bool grounded, Vector2 moveDirection)feeds remote players from a network add-on; the PurrNet bridge uses it
ReStepLandedevent Action<FootStepArgs>fires when a re-step lands
PlantModeenumIdle, Moving, Automatic (follows the locomotion state)
StepSettingsnested classre-step duration, path, arc, lift, rotation and catch-up curves

PlayerFootsteps

On the root. Detects steps from the animated feet, without animation events. Assign stepClips (Step Clips) and optionally reStepClips (quieter clips for re-steps and turning in place). Steps are silent while airborne or standing still.

HandPoseController and FingerPose

HandPoseController (on the model) poses the fingers around the held item on top of the animation. It calibrates itself from the Humanoid muscle limits, so any humanoid rig works.

MemberSignatureNotes
CalibrateFromAvatarbool CalibrateFromAvatar()re-reads the finger limits from the avatar
RebindRebind()rebinds the finger bones
RecaptureReferenceRecaptureReference()captures the reference pose
SnapSnap()applies the current target at once (spawn or equip at start)
ResolvedBoneCountint (property)number of finger bones found

FingerPose is a ScriptableObject (Create ▸ Player ▸ Finger Grip Pose) with five finger curls (thumbCurl, indexCurl, middleCurl, ringCurl, littleCurl), thumbOpposition and spread. Its ToValues() and FromValues(...) methods convert to and from FingerPoseValues.

PlayerVitals is optional and lives on the root. It adds local health and heart-rate based sprint stamina.

Holster timings are Inspector fields under Holster: holsterOffset, holsterTiltAngle, holsterDuration (Holster Duration), drawDuration (Draw Duration), drawStartWeight (the IK weight needed before the draw starts), leftHolsterOffset and twoHandedBlendDuration. PlayerSpineStabilizer

[RequireComponent(typeof(Animator))]. Keeps the upper body steady while the head looks around. Execution order 15, between head and hand IK. Tuned through the spine fields of PlayerSettings.

PlayerHandPoseDebugger (debug)

Debug helper that previews hand and IK poses from the ItemContainer without showing the item mesh. Attach it to the player root.

11 / Add-ons

Multiplayer add-on bridges

The optional add-ons contain one bridge per network library. Both expose the same item-state hook, and both keep a list of networked world item prefabs.
