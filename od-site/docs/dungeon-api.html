Reference

Dungeon API Reference

Documentation for v1.1.0namespace DungeonGenUnity 6000.5.0+

The public API of Easy Dungeon Generator 1.1.0, in namespace DungeonGen. It covers the managers, decoration, rendering and geometry contracts, post-processing and culling, and the authoring assets. For how to use these in a project, read the guides.

DungeonManager#

DungeonManager : MonoBehaviour plans the whole DungeonTemplate first and only then replaces the previous output. Generation is rejected while a run is in progress.

Methods#

MemberDescription
void Generate()Validates the template, plans, materializes the rooms, wires the doors, places progression items, decorates, and runs the post-processors. Also the inspector button Generate Dungeon and the context menu Generate Dungeon.
void ClearAllChildren()Removes the generated rooms and the spawned prototype player. Deferred until the current generation step ends.
void PrewarmForGeneration()Measures the room prefabs and fills the object pool in advance. Safe to call repeatedly; Generate() calls it too.
void AddNavMeshSupport()Adds DungeonNavMeshPostProcessor, with its DungeonNavMeshSurfaceHost and a NavMeshSurface. Does nothing when it is already present.
void AddCullingSupport()Adds DungeonCulling. Does nothing when it is already present. The mode stays Disabled until you set it.

Status and events#

Status DungeonGenerationStatus read-only
State of the latest run: Idle, Generating, Ready, Failed, or Cancelled. A failed run keeps the previous dungeon.
IsGenerating bool read-only
True while Status is Generating.
GenerationProgress float read-only, 0 to 1
Progress of the current run.
StatusChanged event Action<DungeonGenerationStatus>
Raised with the new status each time it changes.

ChunkDungeonStreamer#

ChunkDungeonStreamer : MonoBehaviour plans a (2·plannedRadius+1)² area of chunks around the player and builds a (2·loadedRadius+1)² area. The initial load completes in one call, so the player spawns into a finished world. Later moves are spread over frames. Unloaded chunks stay inactive in a pool and are reused.

Methods#

MemberDescription
bool Initialize()Measures the prefabs and builds the initial area. Returns false, and logs why, when the configuration is invalid. Also the inspector button Generate.
bool UpdateCenterFromPlayer()Moves the streamed area to the player's current chunk. Does nothing while the player stays in the same chunk. Also the inspector button Recenter.
ChunkCoord CenterFromPosition(Vector3 position)The chunk coordinate of a world position.
void Dispose()Destroys the loaded chunks and the pool. Removes a player that the streamer spawned, but never a player you assigned. Also the button Clear World.
void Rebuild()Dispose() followed by Initialize(). Also the inspector button Rebuild.
static int ChunkSizeMinimum(int maxRoomWidth, int maxRoomHeight, int safetyMarginCells)Three times the largest room side, plus twice the safety margin.
static int ChunkSizeRecommended(int maxRoomWidth, int maxRoomHeight, int safetyMarginCells)The minimum plus MainPathWidthCells (2).

IsInitialized bool read-only
True after a successful Initialize().

Serialized fields#

The settings are described in Chunk Streaming settings. The most used ones are:

player Transform, playerPrefab GameObject
The player that the streaming follows. A prefab is spawned at the entry room when no player is assigned.
corridorPrefab GameObject required
A 1 × 1 corridor module with one DoorSocket on each cardinal side. There is no built-in fallback.
useDedicatedEntry bool default on, entryPrefabs List<GameObject>
Dedicated entry rooms for the first room of each chunk. Off = pool-only mode.
roomPrefabs List<GameObject>
Rooms for the pool. Each one must have a DoorSocket on every cardinal side.
minRooms, maxRooms int default 4 and 4
Rooms per chunk, Entry included.
cellsPerSide int default 24, cellSize float default 3
Chunk size in cells, and the size of one cell in meters. The cell size must match the room grid.
worldSeed int default 42, useRandomSeed bool default on
Repeatable world seed, and whether a new seed is drawn each time.
plannedRadius int default 2, loadedRadius int default 1
Planned and built radius in chunks. loadedRadius must not exceed plannedRadius.
lockChance float default 0, keyPrefab GameObject
Random lock fraction, and the key used to open locks.
materializePerFrame int default 1, materializeFrameBudgetMs float default 0
Build work per frame, and the optional millisecond budget. 0 turns the budget off.
prewarmRoomCopies, prewarmCorridorCopies int default 4 and 24
Inactive copies created in advance for the rooms and corridor tiles.

RoomDecorator and RoomDecorationAuthoring#

RoomDecorator is a plain C# class, not a component. It fills a room from a DecorationProfile. The editor preview and the runtime use the same solver. RoomDecorationAuthoring is the component on a room prefab. It holds a baked snapshot of the room geometry, and it creates a RoomDecorator at runtime when it is decorated.

Constructors: RoomDecorator(RoomDesign design, Transform root, DecorationProfile profile, int seed) and RoomDecorator(IRoomGeometry geo, Transform root, DecorationProfile profile, int seed).

MemberDescription
DecorationResult DecorateAll()Clears earlier placements, then solves every category, highest priority first.
DecorationResult DecorateCategory(string categoryId)Solves one category again. Removes its earlier instances first.
void DespawnCategory(string categoryId), void DespawnAll()Removes the instances of one category, or of all categories.
IReadOnlyList<PlacedInstance> PlacedThe current placements.

IRoomGeometry#

The geometry contract for the decorator. It is implemented by RoomDesign in the editor and by RoomDecorationAuthoring at runtime. Members: Width, Height, FloorIndices, TileSize, FloorHeight, WallThickness, CenterPivot, GetFloor(int), InBounds(x, y), IsWallAt(x, y, floor), HasDoorAt, HasRoomDoorAt, IsStairFloorOpeningAt, IsStairCeilingOpeningAt, IsInStairFootprint, Doors, RoomDoors, and Stairs.

Post-processing and culling#

Post-processing contracts#

  • IDungeonPostProcessor: int Priority { get; } and void Process(DungeonPostProcessContext context). The manager runs every enabled processor on its GameObject after generation, highest priority first. Processors with equal priority keep their component order, and DungeonCulling runs last among them.
  • DungeonPostProcessor: an abstract MonoBehaviour with a serialized Priority. Override DefaultPriority to change the value a new component starts with.
  • DungeonPostProcessContext: a read-only snapshot of one run, with RunSeed, Root, Rooms, LayoutRooms, and Connections. It is valid only during Process.
  • IDungeonPreClearProcessor: void BeforeClear(). It runs before the manager clears the rooms, so that a processor can release references to them, for example a baked NavMesh.

DungeonNavMeshPostProcessor#

Implements both contracts and bakes one NavMesh over the whole dungeon per generation. It requires DungeonNavMeshSurfaceHost, which is added automatically. The fields are described in the NavMesh guide. Key fields: agentTypeID, boundsPadding, layerMask, buildOnProcess, useDoorLinks, bakeConnectors, connectorWidth, logErrors.

DungeonCulling and rules#

DungeonCulling is an additive portal-culling post-processor. It reads the room graph and the door states, and changes only the rendering or activation of the rooms. Removing the component restores the normal behavior.

Mode DungeonCullingMode default Disabled
Disabled (0), DisableRenderers (1), or DeactivateRooms (2).
MaxHops int default 4, OcclusionTolerance int default 0
Door distance from the reference room, and how many closed doors a room may lie behind.
ViewDistance float default 60, RevealDistance float default 45
Distance limit, and the smaller distance at which a hidden room becomes visible.
ProtectedNeighborHops int default 1, MaxVisibleRooms int default 0
Rooms kept visible next to the reference, and the visible room budget. 0 means no budget.
PollInterval float default 0.25, MaxTogglesPerFrame int default 20
Seconds between checks, and the number of rooms switched per frame.
ReferenceTransform Transform, ReferencePosition Vector3
The point the culling is measured from. Setting ReferencePosition turns on UseReferencePosition.
DebugDraw bool default off, CullLights bool default on
Scene view gizmos, and whether the lights of hidden rooms are turned off.
UseDoorState, UseMaxHops, UseOcclusionTolerance, UseDistanceCulling, UseDistanceHysteresis, UseProtectedNeighborHops, UseVisibilityLeases, UseRoomRules, UseVisibleRoomBudget bool default on
Switches for each mechanism.
MemberDescription
void Refresh()Applies the visibility to every room now. Use it after you change the state of the rooms by other means.
void PollNow()Checks the door states and the reference position now.
bool IsRoomVisible(RoomData room)The current visibility of a room.
void SetReference(Transform reference)Sets the reference transform.
void SetConnectionRule(ICullConnectionRule rule)Replaces the rule that decides whether a connection is passable.
void AddRoomRule(ICullRoomRule rule), void RemoveRoomRule(ICullRoomRule rule)Adds or removes a room rule.
VisibilityLease AcquireVisibility(RoomData room, string reason = null, float durationSeconds = 0f)Keeps a room visible until the returned lease is disposed, or until the duration ends.

ContractPurpose
ICullConnectionRule: bool IsPassable(DungeonConnectionInfo connection)Decides whether a connection is passable for the visibility search. The default is DoorSocketRule, which passes a connection when both doors are open and unlocked.

Progression contracts#

  • IItemSpawnPoint: bool CanSpawn(ProgressionRequirement requirement) and bool TrySpawn(ItemSpawnRequest request). The default is ItemSpawnPoint, with an optional target transform and prefab override.
  • ItemSpawnRequest: a readonly struct with requirement and roomRoot.
  • ProgressionItemToken: the component on a spawned item, with Requirement and Configure(requirement).
  • IConnectionGate: Requirement, IsLocked, CanHandle(requirement), Configure(requirement), and Unlock(). The default is BasicConnectionGate.

A gate on a door locks the connection until the requirement is unlocked, and an item spawn point in the providing room places the item. The guide Progression requirements describes the setup.
